## Problem

`npm audit` flags zod < 4.6.6 as **high**:
GHSA-mrhx-c7xc-m3w5 — "Zod can exhaust memory while validating oversized
constrained collections" (DoS via `.min()`/`.max()`-constrained arrays of
arrays). The advisory's patched range is only `>= 4.6.6`; **the v3 line has no
patch**, so the fix requires the major bump to `^4.6.7`. zod parses untrusted
model output (`validateLessonOutput` etc. via `src/lib/generation/`), so the
DoS surface is real: an LLM returning a maliciously shaped structure is parsed
with `schema.parse()`.

Related v4 changes that touch this repo:

1. `z.record(valueSchema)` (single-argument) was removed —
   `src/lib/validation.ts:26` uses it (`answers` map).
2. v4 `invalid_type` issues expose `expected` + `input`; the v3 field
   `received` no longer exists — `src/lib/generation/errors.ts:110` reads it.

## Hypothesis

H1: after the bump to `zod@^4.6.7` and the two API adaptations above, all
existing tests pass unchanged in behavior, typecheck and lint stay green, and
`npm audit` no longer reports the zod advisory.

## Metric & data split

Full existing test suite (jest, `apps/desktop`), `tsc --noEmit` typecheck,
